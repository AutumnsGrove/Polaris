Quick Answer

Tokio is the de facto standard async runtime for Rust1 and what you should default to for anything network- or I/O-bound in production. For smaller binaries, embedded targets, or WASM, smol is a lighter-weight alternative built from composable pieces rather than one monolithic runtime3, while async-std trades some of Tokio's performance for a std-mirroring API that's easier to pick up2. Runtimes generally aren't interchangeable mid-project since ecosystem crates target one or the other.
