Tool usage + Jev call counters

Mockups for issues #150 and #151, drawn from the real numbers in the dev polaris.db (9,856 events; last 14 days shown for the time-based views; Jev ledger has 117 calls). Everything is hand-rolled SVG/CSS grid with the app's tokens, no chart library. Latency is not shown anywhere because events doesn't record duration today.

Option A

Heatmap: tools × days

The issue's original idea. Intensity is log-scaled because one big day (Sep 29: 795 calls, mostly Constellation backfill) would otherwise turn every other cell invisible. Red corner dot = at least one error that day. Best for "when" questions.

Option B

Star chart: volume vs. reliability

The "special type of graph": every tool is a star. Horizontal position is call volume (log scale), vertical is error rate, size and glow track volume. Healthy workhorses sit lower right; tools quietly failing climb toward the top, so code_exec, view_image and web_read jump out. Hover or tap shows exact numbers. It fits the night-sky identity and answers "is this tool worth keeping" in one glance, though it says nothing about time.

Option C

Ranked bars with sparklines

The most phone-friendly: one row per tool, bar length is calls (red slice is errors), then error rate. Simple, and extends naturally with a tiny 14-day sparkline per row if you want a time hint.
