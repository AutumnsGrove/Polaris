Settings redesign — three layout options

Built from the live panel's own tokens (--color-*, --radius-*, --space-*, Lexend + serif title, gold accent, the same switch/segmented/select controls). All three share one row anatomy and one disclosure pattern; they differ only in how the 13 sections are organised. Tap the “Why / details” lines to see the expand behaviour.

Mixed section chrome todaySome sections have an icon header + card, some a card with a button, “Updates” has full-width buttons outside any card, Voice has two cards back-to-back with a hint wedged between.
Uneven description weightHints range from nothing (Theme) to a 9-line paragraph (Oracle mode). The long ones push the next section’s header off-screen.
Odd spacingHint sits tight under its card but ~40px of air above the next header, so hints read as belonging to nothing. Pronouns wrap to a second row; “Reading voice” card butts into the Mic hint.
One 2,500px scroll13 sections, no way to jump, and rarely-touched things (Updates, Tools) share equal weight with daily ones (Model, Focus).

AGrouped list — one scroll, tighter structure

Keeps today’s single scrolling sheet, but sections collapse into five labelled groups (the small caps label style the Usage view already uses). Every row is icon + title + at most one dim line; anything longer lives behind a single “Details” disclosure. Least change, least risk.

Pro: everything still visible by scrolling; closest to todayCon: still a long page (~1,400px vs 2,500px)

How it works

Oracle reads each message before answering and quietly adjusts how Polaris answers — for example, taking extra care with sources on a health question. Anything it changes is shown on the reply, and you can undo it with a tap. Off by default.

Each message is also sent to a small helper model; its cost appears under Usage. Ghost conversations stay out of this unless you turn on the second switch.

CTabs on phone, sidebar on desktop — same content, adaptive nav

A segmented tab bar (the control Polaris already uses for Theme/Mic) pins under the title on phone; on desktop the modal becomes a two-pane layout with a left rail. Each tab is a short, scannable page using the shared row anatomy, so it’s one tap to reach anything and only the active category scrolls.

Pro: fast jumping, desktop finally uses its width, one tap to anythingCon: a new navigation concept for the app; tab count is capped (~4 on a phone)
