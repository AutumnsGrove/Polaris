Prism — next blocks

The shipped catalog covers the shapes of an answer (table, procedure, timeline, chain). The gaps left are mostly about sourcing, which is the thing Polaris is for, plus a few phone-specific shapes. Eight candidates, each shown rendered at phone width beside the fence lines that would produce it.

All content is sample data for layout, not real search results. Source chips are drawn the way the real ones render (named, from a [Title](URL) link or a "src" array); a green ✓ on a chip is the verification tick, which the pipeline sets and the model never writes.

1 · Sourcing-native: show where the answer stands

claim handles "is this one statement true". These four handle the other honest situations: a question with real camps, a mix of firm and shaky facts, sources that give different numbers, and "what changed since I last looked".

For "which side is right" questions where the honest answer is that serious people disagree. Not procon (one thing weighed) and not claim (one statement, a verdict). Deliberately no verdict, no strength meter: a model-invented "weight of evidence" number is exactly the unverifiable claim the sourcing rules exist to prevent. Each camp's sources are checked line by line like claim's evidence.

4 · Round two: analogy and readings

Both approved. analogy is a teaching device and has nothing to verify. readings goes the other way: it exists so the answer sends you to the pages themselves, and every rule below is about keeping the model from recommending reading it has not done.

APPROVED

analogy — "X is like Y", and where it stops being true

Think of it as
A postal system
On the networkIn the post
Packet↔Letter IP address↔Street address Router↔Sorting office Port↔Flat number
≠Where it breaks

A letter arrives once and in one piece. Packets can be dropped, duplicated or arrive out of order, and TCP exists to repair that.

{"c":"analogy","x":"On the network","y":"In the post",
 "like":"A postal system"}
{"x":"Packet","y":"Letter"}
{"x":"IP address","y":"Street address"}
{"x":"Router","y":"Sorting office"}
{"breaks":"A letter arrives once and in one piece…"}

Each x/y line is one finished row, so the mapping fills in as it streams. The "breaks" line is the point of the block: an analogy that never says where it fails teaches something false. The prompt asks for it every time, and a block without one still renders (a missing line is just absent, never an error). Up to 6 pairs. It is the model's own device, so no source and no tick; an accent block like define, with no Oracle option.

What makes it send you to the sources, not around them:

  • Only pages Polaris opened. A line's URL must be one web_read fetched this turn, the same evidence set verification uses. Any other line is dropped and counted in the muted note at the foot. The model cannot recommend reading it never did.
  • "Opened by Polaris", the minutes and the page count are measured, not written by the model. They come from the page itself, counted at the moment web_read fetches it: the word count of the full extracted text, taken before the summarizing filter and before the display window trims it, at about 230 words a minute. What the model got back is never used: a two-line answer to a question says nothing about how long the page is. The model only writes the title, the level and one line on why.
  • Cases where a number would be wrong, so none is shown. A PDF shows its page count from the file (web_read extracts one page at a time, so there is no full text to count). A fetch that looks like a paywall stub or an empty JS shell shows no number at all, because "1 min" for a 15-minute article is the exact failure to avoid.
  • Order is the point. Levels render in a fixed order (start, next, deep) however the model emits them, at most 6 lines.
  • Ticks are local. Same rule as checklist: the page remembers nothing beyond the open tab.

highlight says "here are the best few things I found", cards you pick from. readings says "read these, in this order". The Oracle option text has to keep them apart, and a shopping answer should never fire it.

6 · Considered and cut

  • Scorecard / star ratings. Model-invented numbers with nothing to check them against. If a source publishes a score it belongs in facts or rank's v with that source attached.
  • Calculator, converter, countdown. Computed values; decision 1.
  • Distribution or composition charts (pie, bars, sparklines). Decision 6. code_exec renders them better. spread is the only near-miss and is marked Last for that reason.
  • Map / place card. Already parked on docs/plans/interactive-maps.md; reuse that rather than a second map path.
  • FAQ. It is a list of disclose rows; a second block adds a name, not a capability.
  • Option chips. Decision 5; the follow-up suggestions already cover them.
  • Product cards with images. highlight and Shopper mode own this and have verified pages behind the images (decision 4).
